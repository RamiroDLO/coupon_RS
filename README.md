# coupon_RS

Personalised grocery coupon recommendation on the Dunnhumby **"The Complete Journey"**
panel: for each household, rank the coupon-eligible products it is most likely to buy
next. See [`report/report.md`](report/report.md) for the full write-up (problem,
method, evaluation, results) and `PROJECT.md` for the team's working notes.

## Repository structure

```
coupon_RS/
├── report/                 # the graded scientific report + figures
├── src/                    # current pipeline: task builder, baselines, ALS, eval harness
├── scripts/                # runners for the current pipeline (see "Reproducing results")
├── legacy/                 # earlier campaign-/coupon-level formulations, kept for reference only
├── notebooks/01_eda.ipynb  # exploratory analysis backing the report's Dataset section
├── eda/                    # earlier scoping notebook (data-quality checks, six framing questions)
├── docs/                   # pitch deck, dataset user guide, eval-harness SOP
├── artifacts/              # generated CSVs/figures — gitignored, regenerated by scripts/
├── Data/                   # raw CSVs — not tracked in git, see below
└── requirements.txt
```

## Data

The `Data/` folder is **not** tracked in this repository (see `.gitignore`) — the raw CSVs
are large and are excluded to keep the repo light.

The dataset is available on Kaggle: https://www.kaggle.com/datasets/frtgnn/dunnhumby-the-complete-journey/data

To reproduce the notebooks and scripts, download the Dunnhumby "The Complete Journey" dataset
and place the CSVs in a local `Data/` folder at the repo root:

```
Data/
├── campaign_desc.csv
├── campaign_table.csv
├── causal_data.csv
├── coupon.csv
├── coupon_redempt.csv
├── hh_demographic.csv
├── product.csv
└── transaction_data.csv
```

## Reproducing the report's results

Run from the repo root, after the `Data/` folder is in place:

```bash
python scripts/run_baselines.py                  # 8 baselines (incl. item-kNN) -> artifacts/baseline_results.csv
python scripts/run_als_validation.py             # ALS hyperparameter sweep on validation weeks
python scripts/run_als_test.py                   # frozen ALS config on test weeks -> artifacts/als_test_results.csv
python scripts/run_responsible_use_summary.py    # rebuilds the report's §6 evidence table from the CSVs above
```

Every model is scored through the same frozen evaluator (`src/eval_harness.py`, `src/product_reco.py`),
so no metric can diverge between methods. The temporal split, seeds and top-K are fixed in `src/config.py`.
`legacy/` holds an earlier campaign-level and coupon-redemption-level framing of the same dataset (see
`PROJECT.md` § 0); it is not part of the current pipeline but is still runnable — see `legacy/scripts/`.

## Notebooks

### `notebooks/01_eda.ipynb`

The exploratory notebook backing the report's Dataset section (§2): data-quality checks, sparsity,
demand concentration, and the numbers cited throughout §2.4's design implications.

### `eda/01_EDA_Sparsity_Targeting_Signal_Data_Quality.ipynb`

An earlier scoping notebook, from before the project settled on the product-ranking framing. Runs five
data-quality checks, then answers six questions:

1. How sparse is the household x commodity matrix?
2. What does the household activity distribution look like?
3. Does the retailer's own targeting have signal?
4. What's the base-rate coupon redemption rate?
5. Is the test window representative?
6. Does the demographic table cover households at random?

It closes with an executive-summary table and a limitations list.
